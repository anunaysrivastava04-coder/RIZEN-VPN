# Contributing

1. Fork the repository and create a focused branch.
2. Keep changes small and explain the reason in the pull request.
3. Run `npm test` before opening a PR.
4. Do not commit credentials, user logs, real IP addresses, or private proxy details.
5. Update `PRIVACY.md` and `README.md` if behavior or data flows change.

Pull requests should describe what changed, how it was tested, and any remaining limitations.
